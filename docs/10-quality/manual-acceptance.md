# 수동 기능 검증

로컬 또는 전용 테스트 환경에서 [실행 절차](../01-getting-started/run-and-operations.md)를 완료한 뒤 확인합니다. 세션 계정과 API Key의 브라우저 컨텍스트를 분리하고, 삭제·분석은 테스트 데이터로 실행합니다. 아래는 재현 절차이며 실행 완료 기록이 아닙니다.

## 인증과 프로필

1. 가입 필수값·중복 아이디·공백 입력을 확인하고 새 계정으로 로그인합니다.
2. 보호 경로 직접 접근, 로그아웃 후 복귀, 세션 만료 중 요청 취소를 확인합니다.
3. 이름·확인 질문 저장과 새로고침 후 표시를 확인합니다.
4. 현재 비밀번호 오류를 확인한 뒤 정상 변경과 재로그인 동작을 확인합니다.
5. 계정 삭제는 취소 경로와 최종 대상을 확인합니다. 연관 데이터 CASCADE가 있으므로 재사용할 데이터로 시험하지 않습니다.

## 회사·JD·체크리스트

1. 회사 문자열·배열·숫자 0을 저장하고 재조회합니다.
2. JD 필수 필드, 생성·선택·수정·삭제와 상태 전환을 확인합니다.
3. JD 대화 후 추출된 필드가 실제 회사·JD에 반영되는지 확인합니다.
4. 체크리스트 수동 추가·수정·삭제와 AI 생성의 대기·처리·완료·실패를 확인합니다.
5. 생성 실패 초기화, 외부 검색 데이터 부재, 항목이 없는 JD를 구분합니다.

## 지원서와 리포트

1. JD별 지원서 생성·편집·삭제와 선택 이동을 확인합니다.
2. 체크리스트가 없을 때 화면 분석 제한, 크레딧 부족과 API 오류를 확인합니다.
3. 분석 요청의 비용·리포트 ID·상태를 기록하고 완료까지 재조회합니다.
4. 리포트별 질문·등급·근거·버전이 선택한 지원서와 일치하는지 확인합니다.
5. 평가·검토 메모 저장 후 재조회합니다. Resume 검토 상태와 리포트 메모를 별도 필드로 확인합니다.
6. 실패 시 상태·차감 주체·환불 결과를 함께 확인합니다. 자동 재요청으로 추가 차감을 일으키지 않습니다.

## 키와 공유

1. 키 생성·증액·감액·삭제 시 계정과 키의 잔액 이동을 확인합니다.
2. 생성 직후 전체 키와 목록의 마스킹 표시를 구분합니다.
3. 키에 허용한 지원서와 허용하지 않은 지원서를 각각 조회합니다.
4. API Key 모드에서 메뉴와 직접 URL 접근 제한을 함께 확인합니다.
5. 비로그인 컨텍스트의 `/shared`에서 정상 키·삭제된 키·없는 리포트·없는 지원서를 확인합니다.
6. 서버가 허용하는 수정·분석 범위와 공유 화면의 조회 UI를 구분합니다.

## 채팅과 반응형

FAB와 `/chat`에서 대화가 이어지는지, 빈 입력·취소·초기화·늦은 응답이 어떻게 처리되는지 확인합니다. 업무 데이터 질문과 사용 설명서 질문을 나누어 확인합니다.

데스크톱과 390px 모바일에서 긴 한국어 텍스트, 내부 스크롤, 가로 넘침, FAB 겹침, light/dark, 키보드 focus와 modal 닫기를 확인합니다. 브라우저·해상도·사용한 데이터와 실패 조건을 기록하고 확인한 범위만 결과로 남깁니다.
